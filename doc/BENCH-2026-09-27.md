and `bench/ab/` are documentation and harness only).

## Method

- `bench/ab/run.py` drives both checkouts **interleaved** (main, branch,
  main, branch, ...), so drift and thermal effects hit both sides equally.
- Each side has its own kernel bytecode cache and fasl directory, warmed by
  the first round; later rounds are warm starts.
- In-program timings use Shen's `(get-time run)` (CPU seconds); process
  timings are user+sys CPU of the child process and wall clock.
- Reported: **min** (least noise) and **median** over N rounds; the ratio is
  branch min / main min (below 1.00 = branch faster).
- Workloads with golden output (urdr) also record an MD5 of stdout.

Reproduce:

```sh
git worktree add ../shen-lua-main 7fb9744
mkdir -p ../cl-source/ShenOSKernel-42 && ln -s "$PWD/tests" ../cl-source/ShenOSKernel-42/tests
export BASE=$PWD/../shen-lua-main NEW=$PWD OUT=/tmp/shen-lua-ab
export TLA_DIR=/path/to/shencheck/lib/tla URDR_DIR=/path/to/urdr
for s in "deep 1" "micro 10" "bench.lua 7" "boot 20" "coldboot 5" "kernel 3" "tla 5" "urdr 5"; do
  python3 bench/ab/run.py $s
done
python3 bench/ab/agg.py
luajit bench/list_builders_ab.lua 5     # in-process TRMC on/off, branch only
```

## 1. Targeted micro suite (`bench/ab/micro.shen`, `curmain.shen`), N=10

Each hot loop is a `define`d function called once from toplevel.

| case | main min | main med | branch min | branch med | ratio |
|---|---:|---:|---:|---:|---:|
| library call from a file that `load`s the library, x1M (`curmain.shen`) | 3.280 s | 3.479 s | **0.0013 s** | 0.0014 s | **0.0004 (~2500x)** |
| `(do (set ...) ...)` inside a loop, x3M | 0.5745 s | 0.6982 s | **0.0530 s** | 0.0547 s | **0.09 (10.8x)** |
| `set-nth` 7 of 8 (short `[X \| (f ...)]` builder), x1M | 0.9078 s | 1.004 s | **0.6487 s** | 0.6914 s | **0.71** |
| map-shaped builder over 1000 elements, x2000 | 0.2009 s | 0.2112 s | 0.1743 s | 0.1986 s | 0.87 |
| `=` on two distinct equal 50-element lists, x200k | 0.5811 s | 0.6014 s | 0.5621 s | 0.5819 s | 0.97 |
| same-file forward-reference call, x3M | 0.0037 s | 0.0038 s | 0.0037 s | 0.0038 s | 1.00 |
| whole micro file, process CPU | 2.46 s | 2.63 s | 1.58 s | 1.71 s | 0.64 |
| whole curried file, process CPU | 3.42 s | 3.61 s | 0.12 s | 0.14 s | 0.04 |

Notes:
- The same-file forward reference does not move because the kernel
  pre-registers the arities of every `define` in a file before evaluating
  it, so such calls were already direct. The `CALLn` change covers KL-level
  unknown-arity calls (code that reaches `eval-kl` without that
  pre-registration); it is a no-op for this case, not a regression.
- `=` on lists is within noise here. The deep-equal loop is fully traced on
  both sides in this shape; the iterative spine walk matters when the
  recursive version aborts traces (it measured 2.7-3.1 us -> 2.1-2.7 us per
  compare on tla states earlier).
